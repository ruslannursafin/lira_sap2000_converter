# Repository Guidelines

## Project Structure & Module Organization
- Root files: `lira_txt_to_s2k.html` (основной одностраничный конвертер), `README.md` (описание алгоритма). 
- Примеры: `deneme SAP2000[7].txt` и `deneme SAP2000.s2k` для ручной проверки; другие *.s2k/$2k* — дополнительные тестовые выгрузки. 
- Временные/резервные файлы (*.old, *.AutoSave, *.fep*) не изменяйте вручную.

## Build, Test, and Development Commands
- Запуск: открыть `lira_txt_to_s2k.html` в браузере (двойной клик или `start lira_txt_to_s2k.html`). Сборка не требуется. 
- Быстрая проверка: вставить содержимое `deneme SAP2000[7].txt` в левое поле и убедиться, что результат генерируется без ошибок. 
- Экспорт: кнопка “Скачать .s2k” сохраняет файл для импорта в SAP2000.

## Coding Style & Naming Conventions
- Язык: чистый HTML/JS без сборки и внешних зависимостей. 
- Отступы: 2 пробела, код в ASCII. 
- Именование: функции в camelCase (`parseLiraTxt`, `buildS2K`); константы UPPER_SNAKE только при необходимости. 
- Комментарии минимальны; предпочтение самодокументирующемуся коду.

## Testing Guidelines
- Основной тест — ручная проверка конверсии образца `deneme SAP2000[7].txt` и сравнение с `deneme SAP2000.s2k`. 
- После правок проверяйте: количество узлов/элементов в статусе, корректность таблиц нагрузок, сохранение файла без экспоненциального формата чисел. 
- Автотестов нет; при добавлении логики предпочтителен небольшой unit-тест в чистом JS (например, через быстрый `@'...'@ | node -`), но хранить тесты рядом пока не требуется.

## Commit & Pull Request Guidelines
- Сообщения коммитов: короткий повелительный стиль (`Add load parsing`, `Fix area renumbering`). 
- PR: краткое описание задачи, что изменено, как проверено (какой пример запускался), известные ограничения. Скриншот или лог статуса конвертации приветствуется. 
- Не трогать большие образцы *.s2k* без необходимости; если меняете формат вывода, укажите, какой файл использовали для сравнения.

## Security & Configuration Tips
- Не добавляйте сетевые зависимости или удалённые загрузки — приложение должно оставаться офлайн. 
- Проверяйте ввод: обрабатывайте только ожидаемые секции, избегайте eval/динамического выполнения. 
- Храните новые примеры в корне и документируйте их назначение в README при добавлении.
