# LIRA .txt -> SAP2000 .s2k конвертер

Этот проект — одностраничный скрипт (`lira_txt_to_s2k.html`), который преобразует текстовый экспорт ЛИРА (*.txt*) в текстовый файл SAP2000 (*.s2k*). Ниже описан алгоритм, используемые данные и ограничения.

## Как это работает

1) Пользователь загружает ЛИРА-`txt` через кнопку или вставляет его в левое поле. 
2) Нажатие "Конвертировать" вызывает `parseLiraTxt()`, который разбирает вход и формирует модель в промежуточных структурах. 
3) `buildS2K()` собирает строки SAP2000-таблиц из модели. 
4) Кнопка "Скачать .s2k" сохраняет сформированный текст как `model.s2k`.

## Парсинг ЛИРА (`parseLiraTxt`)

- **Выделение секций.** Текст режется на строки, которые группируются по именованным блокам ЛИРА (`Titles`, `Rigid`, `Elements`, `Nodes`, `Restraint & UnionDOF`, `Load`, `Load Value` и др.). Строки между названием и закрывающей ")" входят в секцию.
- **Узлы.** Из секции `Nodes` извлекаются координаты (X, Y, Z) и ID узла из комментария `/* id` (десятичные числа; запятые меняются на точки). Узлы сортируются по ID.
- **Стержни и пластины.** В секции `Elements` читаются числовые токены:
  - Тип 10 → стержень: `i`, `j`, `id` (если нет явного ID — по порядку). 
  - Тип 44 → пластина: четыре номера узлов и ID. 
  После извлечения узлы пластин переупорядочиваются по полярному углу в плоскости XY, чтобы исключить самопересечения. ID пластин перенумеровываются компактно с 1 (строится `areaIdMap` для сопоставления исходным номерам).
- **Закрепления.** В `Restraint & UnionDOF` каждая строка: первый номер — узел, далее DOF (1–6). Формируется булев набор U1–R3 с агрегацией по узлам.
- **Материалы и сечения (`Rigid`).**
  - Код 1.1: считываются плотность `rho`, модуль `E`, коэффициент Пуассона `nu` (в единицах ЛИРА). Вес пересчитывается в kN/м³ (`rho*9.81`). По умолчанию: 25 кН/м³, `E=3e7`, `nu=0.2`.
  - Код 2.2 (прямоугольное сечение стержня): ожидается высота, ширина в сантиметрах; переводятся в метры (`h`, `b`). Для одинаковых `b|h` создаётся одно сечение `RECT_{b*100}x{h*100}` с расчётом площади и моментов инерции.
  - Код 2.1 (пластина): толщина (`thick`). Для одинаковых толщин создаётся одно `SHELL_{thickness}`.
  Материал единственный: `MAT1` с типом `Concrete` (если в имени/type встречается `steel` или `conc`, добавляются таблицы свойств стали/бетона; по умолчанию бетон).
- **Идентификаторы элементов.** Собираются множества `nodeIds`, `frameIds`, исходные `areaIds` (до перенумерации) для проверки назначения нагрузок.
- **Нагрузки:**
  - `Titles`: извлекаются пары `id: имя;`, имя очищается от неалфавитных знаков. Определяется тип `Dead`, если имя содержит `dead`, иначе `Other`. `selfWt=1` только для `Dead`.
  - `Load Value`: словарь номер→величина (дроби через точку/запятую).
  - `Load`: каждая строка → `[target, loadCode, dir, sys, loadId?, value?]` (последнее число считается номером загружения). Значение ищется по `loadId`, затем `loadCode`, затем явное поле.
    - Приоритет назначения: если `loadId != 0` и `target` — пластина → записывается равномерная нагрузка `Dir=Gravity|GX|GY|GZ` (глобальная система), `area` перенумерована через `areaIdMap`.
    - Иначе, если `target` — стержень → равномерная распределённая нагрузка `Uniform`, система `LOCAL` либо `GLOBAL`, направление по `dir` (1/2 → GX/GY для глобальной, иначе Gravity), значения `FOverLA/FOverLB` берутся одинаковыми.
    - Иначе, если `target` — узел → узловая сила по `dir` (1→F1, 2→F2, остальное→F3).
  Нагрузочные паттерны создаются только для имён, встреченных в `Titles`; если не найдено ни одного — добавляется `DEAD` с self weight=1.

## Формирование s2k (`buildS2K`)

Сборка идёт таблицами SAP2000 (в порядке ожидания программы):

- Заголовок `defaultS2KHeader` с программным контролем, степенями свободы, опциями анализа, глобальной системой координат, масс-источником. 
- `MATERIAL PROPERTIES` (общие и механические; расчёт `G=E/(2*(1+nu))`, `UnitMass=UnitWeight/9.81`, при наличии стали/бетона — доп. таблицы 03A/03B с типовыми параметрами). 
- `JOINT COORDINATES` с абсолютными координатами. 
- `JOINT RESTRAINT ASSIGNMENTS` при наличии закреплений. 
- `CONNECTIVITY - FRAME` и `CONNECTIVITY - AREA` (треугольники или четырёхузловые пластины). 
- `FRAME/AREA SECTION PROPERTIES` и `ASSIGNMENTS` с привязкой материалов и рассчитанными геометрическими параметрами (торсионная жёсткость прямоугольника `(b*h^3 + h*b^3)/3`). 
- `LOAD PATTERN DEFINITIONS`, `LOAD CASE DEFINITIONS` и для каждого кейса — таблица `CASE - <name> - LOAD ASSIGNMENTS` с единичным SF=1. 
- Нагрузки: `JOINT LOADS - FORCE`, `AREA LOADS - UNIFORM`, `FRAME LOADS - DISTRIBUTED` (всегда `DistType=RelDist`, координатная система по параметру нагрузки).
- Завершающая строка `END TABLE DATA`.

Все числовые значения проходят через `fmtNum` (без экспоненциального формата; при NaN/Inf → `0`).

## Предположения и ограничения

- Поддержаны только типы элементов: стержни (код 10) и пластины (код 44) из образца. Другие типы игнорируются. 
- Обрабатываются секции, указанные в `sectionNames`; пропуск или изменённые названия приведут к отсутствию данных. 
- Нагрузочные паттерны создаются только из объявлений `Titles`; нагрузки с неописанными номерами получают имя `LC<id>` и используются, но без отдельного определения паттерна они не добавятся в таблицу (SAP может потребовать ручного добавления). 
- Толщины пластин и размеры сечений по умолчанию: 0.25 м и 0.5×0.5 м, если в `Rigid` нет данных. 
- Перенумерация пластин компактна (1..N); нагрузки на пластины используют соответствующую новую нумерацию через `areaIdMap`. 
- Материал один (`MAT1`), тип Concrete; характеристики стали/бетона в таблицах 03A/03B — шаблонные, при необходимости подправлять вручную. 
- Единицы предполагаются: вход ЛИРА в тс и метрах (как в образцах), выход SAP2000 — kN, м, °C.

## Пользовательский поток

- Выбрать или вставить исходный *.txt*. 
- Нажать "Конвертировать" → получить текст *.s2k* справа. 
- "Скачать .s2k" сохранит файл для импорта в SAP2000.

## Быстрый обзор ключевых функций

- `parseLiraTxt(text)`: парсинг секций, сбор геометрии, материалов, сечений, нагрузок. 
- `buildS2K(model)`: генерация таблиц SAP2000 из модели. 
- `fmtNum(v, digits)`: формат чисел без экспоненты. 
- `parseIdList(str)`: поддержка диапазонов ID вида `1-5 8 10-8`.
